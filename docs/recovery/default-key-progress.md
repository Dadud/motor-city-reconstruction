# Default key callback and action routing

`input_default_key` implements the shipped callback `0x6f0580` and router `0x6f0e80`. Disabled callback execution runs the recovered byte-masked fallback without touching the queue. Enabled execution runs the actual recovered pop/scan-translation path, masks its result to 16 bits and routes it. Empty/zero results are still routed; no early-zero shortcut is invented.

The router uses signed comparisons. Values below 256 index the low byte map, including negative indices when mapped within the supplied image. Nonnegative values 256..65535 use the high byte map; signed-positive values >=65536 pass through. A zero map byte preserves the full input bit pattern. A nonzero map byte consumes the code and returns zero even when its handler word is null. Returning action callbacks are invoked only for non-null handler identities; their return values are discarded. Map/handler changes made during an action affect later calls, not the current consume decision.

The handler window starts at `0xb36594`, with maps at offsets `0x104` and `0x204`. All views share one 1024-byte image, so potential handler slots 65 and above overlap map bytes. Synthetic fixtures validate the actual selected handler after image construction and omit combinations whose alias-induced nonzero target is not one of the supplied action bridges. They do not separate or repair the bytes to manufacture an impossible independent table layout. Exact duplicate router inputs are omitted.

Native code supports low-map indices from -260 through 255, reachable extended high-byte indices 1..255, and signed-positive pass-through values. Other negative indices are outside the provided image and rejected; original invalid accesses are not emulated. Callback, scan-state and fallback helpers remain explicit returning bridges; original assets/table bytes are not published.
