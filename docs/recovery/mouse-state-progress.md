# Mouse state setter

The complete setter `0x6efaf0..0x6efcad` (446 bytes, one Ghidra body range) is implemented using references to the lifetime words and separate access-mode, state-eight/state-nine and diagnostic observations. REA Evidence `ev_22ef938bbe58d31fcf48eb8ddfc827dd7dec8cff92c6c4082419d8189b9aa633` records Ghidra 12.1.4, target SHA-256 `28c0cdde77ed24bac6aeeea65699c16be0f31e6aa8cb5db38417f0f3d5880164`, profile `3de5374fadd78e0d56219c4afc6b4f2efac7101ff92b72faf375fb0070bbc896`.

Selectors three/four store X/Y and move the cursor when access mode is four; five stores the opaque lifetime word. Eight/nine store separate words at `0x8c8918/1c`. Invalid selectors set diagnostic file `0x84a004`, line `0x185`, invoke the current diagnostic callback with `0x849fe8`, then return false. A missing interface during an access change reports line `0x155` and message `0x84a010`, then still stores the requested mode and returns true if the diagnostic callback returns.

Changing to mode four unacquires the current device, reloads coordinates, positions the cursor and stores the requested mode. Other modes use cooperative flags five for mode five, otherwise six. The function captures the virtual-table base before getting the window, resolves slot `0x34` after that helper, and reloads the current device identity as the this argument. A failed cooperative call attempts unacquire; only statuses zero or one permit retry. The retry again captures the table before getting the window and always invokes the current device's acquire slot afterward, regardless of retry success. It stores the requested mode even when returning false. These are static observations corroborated on the finite fixture domain.

3,168 original-instruction cases cover selection, return paths, HRESULT retries, returning diagnostic mutations, mutable handles/tables, and mutation of the cooperative slot inside the captured table. The bridge therefore accepts an opaque table identity rather than a prematurely resolved function identity. Defined Boolean results are compared in the original AL byte; incidental upper register bits are excluded.

`InputMouseRuntimeBinding` connects position changes to recovered geometry and the window getter to the shared queue's device-window word. Its connected verification is described in [the batch checkpoint](mouse-batch-progress.md). Real COM/window adapters, faults and concurrency remain outside the bridge domain. All referenced observation words are distinct in these fixtures; this API does not establish arbitrary aliasing semantics.

## Cursor update handler under reconstruction

Ghidra 12.1.4 Evidence `ev_2db50ae0ec6ad8eb76fa88e7f8591082f33a09fb7928be4939ea2f548c1972e` identifies `0x4ad6f0` as one contiguous 2,444-byte function (`0x4ad6f0..0x4ae07b`). It first advances keyboard state, then selects DirectInput mouse deltas or mapped cursor state based on controller readiness, input mode, and environment mode. Its later work builds key/button transition masks and updates edge-trigger state. The direct child `0x4606b0` is translated in `client/keyboard_input_state.py`; 256 original calls match the full keyboard record table and directional mask with the record resolver and zero-memory service represented as explicit bridges. `0x6efcd0` is source-complete across its selector dispatch: scalar selectors 7/8/9 match 1,536 original calls; selector 6 absolute and DirectInput modes match 1,024; selector 2 matches 256; invalid selectors match 512. Its info buffer, full output state, and diagnostic effects are compared; `0x6f07a0` runs natively in absolute-cursor cases. The DirectInput path now composes the translated `0x6f0a30` acquire/read/clear wrapper, itself matched across 512 cases, with acquisition and device-read operations left as explicit services. The standalone clamp leaf `0x6f1380` matches 1,000 calls including reversed bounds and signed extremes. The complete `0x4ad6f0` input mapping and transition loop remains open; do not treat these child comparisons as coverage of the full handler.

The next direct child of 0x4ad6f0, 0x460950, is now implemented with its helper 0x460890 in client/keyboard_action_state.py. The helper reproduces signed 24-bit progress thresholds from the 511-entry action table; the predicate covers the type-1 threshold, type-4 held-key and directional mappings, and signed-byte dispatch for other action types. All 4,096 helper calls and 2,048 predicate calls matched the original executable exactly. The external action-state callback remains a boundary. This advances one keyboard predicate used by the handler; its transition loops and complete mouse/input mapping remain unfinished.


The action-edge and transition-ring tail of `0x4ad6f0` now has executable source in `client/mouse_action_updates.py`. It reproduces the shared type-5/type-6 rising-edge latches, priority-ordered key edges, the 32-action mask (including directional mapping bits), increment-before-index ring insertion, and the five-byte notification payload. The action query uses `0x460950`; priority action callbacks remain a separate explicit dispatcher boundary. The native verifier executes the original subregion beginning at `0x4adda2` and compares 256 randomized full state snapshots, including every ring word, edge byte, output payload, and callback order. This recovers the action tail, not the preceding cursor acquisition and movement calculation or the full handler.


The prelude now has bounded executable source for the motion range `0x4ad747..0x4ad868` in `client/mouse_cursor_motion.py`: it forms center±radius bounds, requests cursor recentering for out-of-range samples, clamps the sample, applies the float deadzone and directional ±127 scale, and updates the 60-frame center timer. All 512 randomized original instruction-range executions match, including setter calls. The adjacent mapping copy/Boolean normalization at `0x4ad869..0x4ad8c5` is in `client/mouse_mapping_snapshot.py`; 1,024 randomized original ranges match. Together with the action-tail comparison, this advances the handler source while leaving selector-six acquisition, earlier keyboard-state gating, external callbacks, and full-function composition open.


`client/mouse_update_frame.py` now connects the existing selector-six getter and its acquisition/read bridge to cursor motion, button mapping publication, and transition-ring updates. It preserves the native failed-read behavior by consuming the wrapper-cleared 16-byte sample, and keeps cursor setting, action dispatch, device services, and notification injectable. Successful and failed-read integration fixtures pass; the underlying motion, mapping, and action ranges remain independently compared to original machine code. This does not yet reconstruct the full handler entry gates or compose a complete native `0x4ad6f0` execution.


The inactive-controller branch at `0x4adc28..0x4add70` now has source in `client/mouse_fallback_state.py`. It dispatches the first four configured action words unconditionally, skips later entries whose low type byte is zero, computes the signed half-difference output, stores the next two callback bytes, and assembles transition flags. The native verifier matches 512 randomized instruction ranges including callback order. `update_mouse_fallback_frame` joins this branch to the common edge/ring logic without acquiring a mouse device. The `0x4ad6f0` entry gates and complete-function native composition remain open.
