# Free-camera handler recovery

Original `0x433820` is implemented as `free_camera_update`. Its current context lies at offset `0x100` in a 512-byte observation image; saved reset state lies in the preceding bytes. Registered fields identify position, orientation, sensitivity, spatial record, subject identity, motion, and reset timestamp. These are byte-image contracts rather than recovered C++ class/ownership claims.

The handler preserves reset copying, modifier-key speed changes, one-shot reset queries, sensitivity adjustment, ordered rotation updates, local-to-world movement, subject surface copying, and final spatial lookup. Original `0x413810` is a RET-only child and has no native state effect. All substantive key-query, rotation, and spatial children call recovered implementations. Subject surface resolution occurs after reset because reset may replace the active subject identity.

Verification: 202 complete original calls match MSVC and Zig exactly, with no substitutions. Inputs cover single and combined controls, deterministic random key combinations, alternate raw key byte values, latch patterns, saved/current subject presence, two orientation matrices, three sensitivity values, reset, updates, and ignored event values. Synthetic worlds in these handler cases exercise actual empty-grid/path fallback; the separate 1,200 surface-controller cases exercise candidate hits and cache paths. Every camera, key, latch, and subject byte is retained and compared.

Native tests additionally check movement across repeated frames and reset press/hold/release/repress behavior. Key bytes in the 202 handler observations are planted directly. Four connected message-producer-to-camera traces now match the original under both compilers. Each trace has 27 operations using shared queue/raw-key/latch/camera state. They cover press/release, scan remapping, both shifts, repeated frames, translation, speed/sensitivity modifiers, reset press/hold/repress, and queue resizing. Only critical-section imports are substituted. Full state is observed after each operation, with each new synchronization snapshot retained once. The lifecycle probe is included in fresh capture and aggregate comparison. The corpus has 76 cells, 33,387 routine cases and 36 connected traces. Live window dispatch and actual critical-section behavior remain unresolved.

The supported domain inherits the child routines' finite numeric bounds and mapped memory contracts. Camera, keys, latches, subject surfaces, and world images must be distinct. Arbitrary original access faults, floating-point exception state, and live context ownership are unmodeled. Whole-game acceptance remains open.

Checkpoint checks: full native suites pass 157 MSVC tests and 159 Zig tests; Python discovery passes 987 tests with seven skips. Both aggregate comparisons pass all 76 cells and 36 connected traces, including fresh hash-checked original execution under MSVC. The refreshed inventory records 140 explicitly reviewed main-executable entries. These review counts are not a project completion percentage. This checkpoint advances an emulated input-to-camera path, while live window dispatch, actual synchronization, camera-controller ownership/frame dispatch, linked-client startup, and full-game acceptance remain open.
