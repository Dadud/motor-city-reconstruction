# Native spatial query recovery

Grid lookup `0x552880` is recovered as `spatial_grid_lookup`. The API takes explicit grid/node memory views, coordinate origins/scales, and a diagnostic bridge. Original addresses are opaque node identities; host code never dereferences them.

The function computes X/Z in double precision, stores each scaled coordinate as float, then converts to signed integers with nearest-even rounding. It indexes the 64-by-64 grid using 1024-unit cells and descends at most two quadrant levels. Child order is low-X/low-Z, high-X/low-Z, low-X/high-Z, high-X/high-Z. A `0xdeadbeef` first word marks a leaf. Null children return zero. Excess tree depth invokes the explicit diagnostic bridge with original message identity `0x89900c`, then returns zero. Invalid mapped pointers throw instead of emulating original access faults. Other floating-point rounding modes and exception status are outside the supported domain.

Verification: 1,826 synthetic original observations match MSVC and Zig exactly. Cases cover rounded grid/child boundaries, ties, outside coordinates, direct leaves, one/two-level trees, nulls, corrupt depth, and nontrivial origins/scales. The only substituted original child is `0x4400a0`, replaced in the CPU-only oracle with an observed returning diagnostic. Grid lookup code itself is unchanged. Native tests also cover unmapped-pointer rejection and unsupported rounding modes. All observations are retained in the main regression corpus; fresh capture is wired into `tools.w0_cell_corpus`.

This adds one cell, bringing the corpus to 72 cells and 26,153 routine cases. The four prior queue and other lifecycle probes remain separate. These are bounded evidence counts, not full-game progress percentages.

The nearest-path-point helper `0x42e6b0` and path-side helper `0x42ee50` are now recovered too. Their 1,512 and 4,320 original observations respectively match both compilers without substitutions. Focused native tests cover group indexing, nonpositive count behavior, strict ties, side orientation, last-point wraparound, and bounds rejection. Path positions are explicit supplied views of the original records. Nearest selection stores the Z delta as float, retains the X delta at double precision, compares each unrounded candidate with a float-stored minimum, and rounds only on updates. Path-side products retain double precision. The complete track-surface controller `0x42e760` remains unfinished. Existing Python track layout research is a reference, not proof of native equivalence. Live track ownership and the actual diagnostic/logging implementation remain unresolved.

With both path helpers retained, the corpus has 74 cells and 31,985 routine cases. Full checkpoint verification and inventory refresh are still pending for this spatial batch.

## Track-surface controller

`0x42e760` is now implemented as `track_surface_lookup` using the actual recovered grid, nearest-point and path-side functions. Its 1,200 original cases run without child substitutions and match MSVC and Zig exactly. Synthetic worlds exercise cached containment, empty/outside queries, candidate ordering, upward-facing rejection, previous-block/neighbor acceptance, and nearest-block/path fallback. Record bytes, including retained coefficients, are compared in full. Focused native tests verify cached-hit state isolation, fallback reset/retention, and invalid path-count rejection.

`TrackSurfaceWorld` supplies bounded memory views and original address identities explicitly. World, record and query images are distinct; valid mapped paths/geometry are required. Path count is bounded to one million for host allocation. Arbitrary pointer aliasing, access faults, and live world ownership remain unmodeled. This removes the known spatial helper dependencies of the free-camera handler; the handler itself still requires recovery and integration. The corpus now has 75 cells and 33,185 routine cases. Full checkpoint checks and inventory refresh remain pending.
