## Initial combined sessions

Four new persistent original-execution traces now span actual initialization, state acquisition, polling/read/retry/clear, key/character producers, translation, queue peek/pop, cleanup, shutdown, repeated initialization and reads after teardown. They use the production lifetime/access and translation/device bindings, sharing interface/device and diagnostic references. Platform virtual calls and lock imports remain supplied bridges; recovered game routines execute unchanged.

Three sessions run 21 original calls each. They cover successful initial setup, failed keyboard reads with payload clearing, acquisition retry, changed temporary/device handles, changing vtables, repeated peek/pop and a high-bit stored character. A fourth 11-call session repeatedly fails format setup and verifies disabled acquisition. Total: 74 complete original calls. Queue consumers use raw scan paths in the two preinitialized/raw-mode profiles; the fresh initialization profile preserves the original raw-mode reset. No queue operations are invented after failed setup.

Each step compares result, complete lifetime/queue/key/remap images, synchronization observations, all synthetic table identities, keyboard image, caps/exit state, lookup-table window and accumulated platform observations. The original capture additionally audits result/handle/initialized/cursor/caps values and acquisition call counts per step. It rejects a disabled read that returns an image or calls the device, and an enabled read that fails to execute acquisition. The observed acquisition-call totals are 8, 16, 20 and 0 for profiles 0 through 3. Cleanup/shutdown results are normalized as void; host stack addresses and pointer images are not published.
