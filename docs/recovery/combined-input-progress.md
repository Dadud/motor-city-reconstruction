# Combined input, diagnostic and thread startup

The `combined_input_lifecycle` probe connects recovered startup, diagnostic initialization, thread runtime initialization/allocation/capacity, mouse initialization, keyboard initialization/layout, NumLock, keyboard transitions, mouse geometry/reporting and shared reverse cleanup/restart. Fifty-six persistent 21-step traces execute original x86 instructions with synthetic returning COM, OS, environment and parser boundaries. Both MSVC and Zig Release/NDEBUG comparisons pass.

`CombinedInputBinding` routes startup identity `0x6be4f0` to the recovered thread initializer using caller-owned persistent `StartupThreadRuntime` and the same cleanup registry already used by mouse and keyboard. That initializer executes recovered capacity and page-allocation children. Three additional direct capacity calls are interleaved with input and cleanup operations to check cached allocation identities, retries after failure, and callback changes to allocation/capacity. Four thread profiles cover successful resource calls, failed VirtualAlloc, failed DuplicateHandle, and memory-clear bridge state mutation. The existing seven mouse/keyboard failure pairs and two NumLock states remain.

Original thread cleanup identity `0x6be3b0` is registered in the real shared registry, and reverse cleanup invokes it in its original relationship to input cleanup entries. Primary REA batch `ev_ad498686d6aed10926f7d86e7c59efd9a0e7a535b4e5bcfb167131bd6324db5b` explicitly reports no procedure at `0x6be3b0`; the nearby cleanup routine at `0x6be3e0` is not substituted for it. Its body remains an explicit observed callback boundary: the adapter logs its invocation and returns without freeing resources or resetting thread state. Thus repeated startup preserves initialized state in this declared synthetic model; genuine shutdown/reinitialization is not claimed.

The original storage aliases are preserved: the keyboard translation image at `0x8c8748` includes mouse mode/state words at byte offsets 460, 464 and 468 and the callback at 476. `InputSharedTables` exposes a word-backed byte image without C++ aliasing violations. After every operation the probe compares existing full shared images and words, diagnostics, all eight thread words, the 64-slot shared registry, and ordered thread boundary argument/state snapshots.

`tools/startup_thread_runtime_oracle.py` provides the reusable explicit resource adapter. Its lock-pool and memory-clear substitutions are scoped to callers inside recovered thread capacity setup; unrelated keyboard synchronization and memory clearing retain their existing adapter/original behavior. GetSystemInfo and handle/allocation imports are synthetic; no host resources are acquired. Primary thread REA evidence is retained privately in `evidence/startup-thread-runtime-primary.bundle.json` and snapshot.

This remains a connected synthetic input/runtime probe. Renderer, operating system, hardware, actual resource lifetime and full game startup remain unverified. Diagnostic environment/parser calls and thread cleanup remain declared boundaries.
