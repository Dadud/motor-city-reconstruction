# Console input core recovery

The `input_console_read` batch implements read wrapper `0x7b0cd6`, availability wrapper `0x7b0e17`, unlocked read `0x7b0d0e`, unlocked availability `0x7b0e33`, scan decoder `0x7b0f33` and open helper `0x7b1fe9`. Console APIs and lock/unlock remain explicit bridges; their selected original caller bodies run unchanged in comparisons. This is not a claim of live console or keyboard support.

Wrappers lock identity 8 and preserve the inner result across unlock. Pending values other than UINT_MAX make availability true, and reads return their low byte then clear the pending word. Handle -2 selects initialization; -1 bypasses APIs. Availability checks failed-open validity afterward, while read does not add that recheck. The open helper requests CONIN$ with access 0xc0000000, sharing 3, creation 3 and other arguments zero, and stores the returned handle.

Availability allocates the reported number of 20-byte records, checks count/peek status and returned bounds, filters type/key-down fields, and accepts a nonzero ANSI byte or decoded pair. It does not consume the provider's event stream. Reads temporarily set console mode to zero, consume records until a qualifying key or API failure, and restore the supplied saved mode through the current handle on every normal completion/error path. Return values from get/set mode are ignored, matching the original. The platform contract supplies a defined saved-mode output even when its reported status is failure; original uninitialized outputs and allocation faults remain outside verified scope.

The decoder reads sixteen-byte key records. Alt takes priority over control, then shift, then normal. Matched enhanced rows return their pair without normal-pair validation; normal pairs require first byte 0 or 224 and a nonzero second byte. Read copies both selected bytes before writing the second into pending storage. The 2,168-byte mapped table/state window includes twelve ten-byte enhanced rows, 256 mapped normal scan rows, pending word at offset 0x340 and input handle at 0x400. All views share this byte image, preserving normal-row aliases at scans 89 and 113. Normal scans above 255 are outside the supplied view; enhanced scans may use the full ushort domain.

Verification: 1,932 complete original cases match MSVC and Zig across all six routines. Cases cover pending-byte and handle sentinels, lock/API mutations, initialization failures, status/count/peek failures and bounds, event filtering, ANSI bytes, modifier precedence, matched/missing enhanced rows, invalid normal pairs, overlapping state/table bytes, handle reloads, ignored mode status and mode restoration. API observations retain method, arguments, handles, pending state and consumed-event position; final full data images and results are exact. Two dedicated original read cases verify extraction of a pair that aliases the pending word before that word is overwritten. Temporary out-buffer bytes are populated before use; undefined stack contents are not asserted as recovered behavior.

Four ten-call original traces run persistent availability/read/pending behavior through the actual fallback, dispatcher and disabled default-key callback using `InputConsoleDispatchBinding`. They include decoded two-byte input, later buffered reads, read errors/EOF masking, callback state mutations and repeated calls. Peek observations are relative to consumed stream position. All 40 calls match under both compilers. Independent native tests check buffering, filters, mode restoration, failed-open asymmetry, alias ordering, saved returns, EOF masking and forwarding of other callback contexts.

The retained corpus contains 95 implemented cells, 57,116 routine cases and 76 connected traces. Full checkpoint verification passes: fresh hash-checked original execution against MSVC and retained original observations against Zig verify all implemented cells and connected traces. CTest passes 176 MSVC and 178 Zig tests; Python passes 993 tests with seven skips, and all 35 targeted metadata/corpus/layout checks pass. The refreshed 29-module inventory retains 79,518 entries and 172 explicitly reviewed entries. The wrappers sit in a mixed GUI/runtime region, so no coarse region or library classification was changed. Actual API/lock adapters, action configuration/implementations, uninitialized-output/allocation-fault paths, live input and process cleanup remain unfinished.
