# Keyboard layout selection recovery

Original startup helper `0x6f09f0` caches the `GetKeyboardType` IAT entry at `0x83b3d4` in ESI, calls it with kind 0, and queries kind 1 only if the first result equals 7. Signed subtype values `0xd01..0xd04` select original remap identity `0x8c8930` by writing queue word `0xacae18`, then return one. Rejected types/subtypes return zero without clearing or restoring the remap word. A callback mutation to the IAT affects a later helper invocation, but does not replace the cached function during the current two-query invocation. The native bridge preserves that distinction.

The 128-byte selected remap starts at offset `0x1e8` of the existing 620-byte scan-translation image (`0x8c8748`). It is an aliased view, not a copy or separate initialized table. `input_keyboard_remap` exposes that view. `window_keyboard_layout_binding` selects it for the known remap identity and forwards through the recovered keyboard handler binding. Other nonzero identities still require a caller-supplied mapped remap view; no arbitrary original pointer becomes a host pointer. No static original table bytes are published.

560 complete original helper cases match MSVC and Zig. They cover type rejection, all four accepted subtypes and neighboring/signed bounds, initial null/other/selected/opaque remap words, callback changes to remap/raw-mode/table data, API-target mutation, exact call order and cached query identity. Results, queue/key/remap/translation images, API target and callback observations are exact. Independent native tests check accepted/rejected branches, callback-visible state, query caching and live view aliasing.

Four 22-operation original traces connect selection to actual key-down, release, key query/latches, peek/pop and scan translation. They include successful/failed setup, later setup after API-target mutation, byte changes between messages, remap to both Shift scans and byte scan 255, explicit pointer clearing, caps processing and a translation read overlapping the remap bytes. All 88 operations match both compilers. Queue, raw keys, alternate remap, translation data/state, latches, synchronization and type/provider observations remain shared throughout each trace. Table/pointer writes are explicitly fixture operations, not claimed game configuration functions. Synchronization, type queries and state provider remain returning bridges.
