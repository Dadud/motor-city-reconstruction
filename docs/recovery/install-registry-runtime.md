# Install registry runtime recovery

Recovered complete original routines: constructor `0x51d330`, reopen `0x51d580`, is-open predicate `0x51d490`, and language query `0x530ab0`. Primary REA facts and instruction evidence are retained privately in `evidence/install-startup-primary.bundle.json` and snapshot, pinned to mcity.exe SHA-256 `28c0cdde77ed24bac6aeeea65699c16be0f31e6aa8cb5db38417f0f3d5880164`. Evidence IDs are recorded in the cell manifest and review batch.

The owner representation is the original 0x210-byte image with explicit little-endian access. Every untouched byte is preserved and compared, including bytes after the key/path first characters and the bounded copy boundary. Construction stores original vtable identity 0x83ec68, zeros handle and the first bytes of the key and module path, invokes path initialization, then conditionally closes a handle that the path boundary may have installed. Reopen closes only a nonzero old handle and clears only the handle and two first bytes before opening. Open failure clears the returned handle but preserves other stale bytes. Success executes the original bounded 259-byte copy boundary. Predicate checks the full 32-bit handle.

The language helper preserves query metadata initialization (type=4, size=4, value=0), query/close ordering, ignored query/close return statuses and final language assignment after close. Its supported domain requires successful open with an explicitly written output handle. The original failed-open path can consume an uninitialized local handle and is deliberately excluded. Partial query writes and query failure with no value write remain covered, including metadata changes that do not alter the final value semantics.

Path initializer `0x51d3c0` is a real executable-directory/mcotest.ini builder, not a close/reset helper, and remains an explicit path-preparation boundary. Registry open/query/close and strncpy remain explicit callbacks. Synthetic registry values are generated fixture words; no real registry, account values, credential storage or host resource writes are used.

`tools/install_registry_runtime_cases.py` captures 1,024 fresh complete-body original-instruction cases. Inputs include byte-pattern owner images, existing/null handles, status failures, successful zero handles, path-helper handle mutation, close/open/copy owner mutation, and source lengths 0, 3, 258 and 300 with a 259-byte copy. Every owner byte, language global, return word and boundary argument/pre-state image is compared. MSVC and Zig comparisons pass; native NDEBUG domain tests reject the unsupported language open failure. These bounded comparisons do not establish live Windows registry/startup behavior.
