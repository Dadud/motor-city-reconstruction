# Device information recovery

The complete `0x6f0b20` information enumerator is implemented as `input_device_information`. It clears its 540-byte output, requests a 580-byte instance record, copies device type and two 259-byte padded names, then requests a 44-byte capabilities record. Capability bits 0 and 8 replace output flag bits 0 and 1 while preserving other output bits. The decompiler's apparent incoming-EBX dependency is a misidentification: instructions load those flags from the capabilities record.

Button probing accepts device-type low bytes 2 and 4, using offsets 12+index and 48+index respectively. Up to 32 button, eight supplied-axis and four POV-offset probes run, stopping when each reported successful count is reached. Failures do not count toward the requested total. Device type and counts are reloaded after callbacks, and each virtual call reloads the vtable. The 316-byte object record is initialized with its size once and reused, preserving platform writes between probes. Final return status comes from instance/capabilities acquisition; individual object failures only affect masks. Instance and capability failures retain their original partial output behavior.

The bridge exposes original-sized temporary records and opaque device/vtable identities. Only the size tag is defined before a record's first virtual call; the platform must populate every subsequently read field. Host zero initialization of other temporary bytes is not a claim that the original cleared them. Axis offsets are supplied explicitly, and original table bytes are not published.

Verification: 806 complete original cases match MSVC and Zig exactly. Cases cover type high bits, zero/one/boundary/over-limit/UINT_MAX counts, all/none/alternating/selector-dependent probe success, both early failure stages, padded/truncated name boundaries, flags, mutable vtables, device type, counts, output masks, axis offsets and record size tags. Comparisons retain final status, full information output, axis offset image and ordered callback observations of table, method, selector, flags, size tag and pre-call output. Synthetic stdcall virtual methods preserve real callee cleanup; original enumeration, copies and clear code execute unchanged.

Independent native tests check masks, capability mapping, hard probe limits, successful-count stopping, names and padding gaps, table reloads, changed size tags, type/count changes and early failures. Four additional persistent traces execute information and keyboard acquisition through the actual state accessor, including repeated access, instance/capability failures, callback mutation and diagnostics. `InputDeviceInformationBinding` preserves keyboard resolution/diagnostic contexts while wiring the real enumerator. Both compilers match all four traces.

The retained corpus contains 91 implemented cells, 48,392 routine cases and 48 connected traces. Full checkpoint verification passes: fresh hash-checked original execution against MSVC and retained original observations against Zig cover all 91 cells and 48 connected traces. Native CTest passes 172 MSVC and 174 Zig tests. Python passes 989 tests with seven skips; the 15 corpus/layout checks pass after inventory refresh. Inventories record 157 explicitly reviewed main-executable entries. These counts do not measure whole-game completion. Platform methods, initialization/lifetime, live input and process cleanup remain unfinished.
