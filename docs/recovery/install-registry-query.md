# Registry create, close and integer read recovery

The package recovers close/reset `0x51d1d0`, key creation `0x51d520`, direct DWORD read `0x51d6c0` and conditional-commit wrapper `0x51d690`. Primary REA instruction evidence and selected decompilation are retained privately in `evidence/install-registry-query-primary.bundle.json` and snapshot; individual evidence IDs are listed in the cell manifest. All observations are pinned to the original mcity.exe SHA-256 `28c0cdde77ed24bac6aeeea65699c16be0f31e6aa8cb5db38417f0f3d5880164`.

Close resets the vtable identity even when the handle is null. For a nonzero handle it invokes close, then clears the handle and only the key/path first bytes; the remaining owner bytes stay untouched. Creation uses the same conditional old-handle reset, then calls RegCreateKeyExA. It returns status==0 and preserves whatever handle the creation boundary writes even when status reports failure. Unlike reopen, it does not clear that returned handle. The original prologue PUSH ECX at `0x51d523` initializes the disposition local with the original owner identity; this instruction fact is retained even though a newer decompilation obscures the initialization.

Direct integer query requires a nonzero handle and name identity. With both owner key/path first bytes nonzero it tries a zero-initialized 256-byte profile text buffer with API size255. Nonzero result and nonempty text select the `%u` scan boundary and return true regardless of the scan result or whether it wrote output. Otherwise it rereads the live owner handle and executes a DWORD registry query with type4 and size4 metadata. Success requires status0, resulting type4 and any nonzero size; size need not remain4. Output changes are preserved even if those checks fail.

The wrapper initializes its temporary DWORD from the input name identity, calls the direct query into that local and copies it to the external output only on success. Consequently a failed text scan can still return success and copy the original name identity; partial registry writes preserve the name word's unwritten high bytes. Direct queries preserve the external output's own high bytes instead. These quirks are tested explicitly rather than replaced with a cleaner conversion policy.

The synthetic adapters use corrected original import slots: create0x83b020, profile0x83b300, close0x83b010 and query0x83b028. Registry owner/output, live metadata and text-buffer views remain explicit platform boundaries; no host registry/profile files, actual accounts or credential values are accessed. Source identifiers remain opaque original-sized words and are never dereferenced by native code.

The corpus contains 1,280 fresh complete original-instruction cases: 1,024 single-call cases and 256 persistent six-operation sequences `[direct query, wrapper read, create, direct query, close, wrapper read]`. Each sequence compares return bits, all528 owner bytes, the external4-byte output and ordered cumulative boundary records after every operation. Fixtures cover null/nonzero handles and names, missing key/path text, profile empty/nonempty and scan failures, query status/type/size rejection, successful partial/full query writes, failed creation retaining an output handle and callbacks mutating the owner. Handle/name flags are deliberately independent of query success profiles so ordinary and partial successful reads are exercised.

MSVC and Zig NDEBUG comparisons pass all cases. Native Release-active tests verify ignored scan status, name-initialized wrapper output, partial high-byte preservation, wrapper failure noncommit and mandatory bridge rejection. These are bounded original-instruction comparisons with declared returning bridges, not live Windows API or game acceptance.
