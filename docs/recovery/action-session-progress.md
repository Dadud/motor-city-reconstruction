# Initialization through default action sessions

Four new persistent original-execution traces connect device initialization, shared interface/device/diagnostic globals, actual acquisition/retry/clear, character/key producers, callback selection, the shipped default callback, pop/scan translation, overlapping action routing, cleanup, shutdown and reinitialization. Each session executes 25 complete original calls, totaling 100. Platform methods, configured actions and fallback helpers remain supplied bridges; recovered game bodies execute unchanged.

Profiles cover fresh initialization; preinitialized/raw input with failed keyboard reads; acquisition retries with changed device/temporary handles and action-map mutation; and setup failure with disabled acquisition. Actions can clear the callback/gate, so subsequent dispatch uses fallback while direct state acquisition still observes the separate interface handle. The changed-map profile preserves action data through cleanup/reinitialization. A non-default synthetic callback after teardown verifies forwarding of the original platform context and full return value. No invalid queue translation is forced after teardown.

The new harness uses production lifetime/access, translation/device and default-key/dispatch bindings together. The acquisition fixture was extracted into a shared header without behavior changes; all eight prior device sessions continue matching exactly under both compilers.

Every step compares complete lifetime/queue/key/remap/keyboard/lookup/action images, handle/table identities and accumulated platform, synchronization, action and fallback observations. The original capture audits operation arguments, result, handles, gate, callback, initialization flag, cursors and acquisition/action/fallback counts. Disabled state reads must return null without acquisition calls; enabled reads must execute acquisition and return the original keyboard view. Final acquisition/action counts are 4/2, 4/1, 12/2 and 0/0 across profiles 0..3.

All four sessions match MSVC and Zig. The corpus now contains 94 implemented cells, 55,184 routine cases and 72 connected traces. Their union-field labels and dynamic-stack draft need instruction-level review before typing records or claiming a library equivalent. The current coarse disposition marks the fallback helper block `0x780000` as game code because it also contains GUI primitives; the lock/unlock helpers are in an excluded library block. A library-equivalence claim still needs matching state and error behavior, not just similar API names.
