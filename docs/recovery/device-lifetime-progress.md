# Device initialization and lifetime recovery

The `input_device_lifetime` batch implements initialization `0x6f0200`, cleanup `0x6f0310`, registered shutdown callback `0x6f0350`, set-state `0x6f0360`, and window getter `0x584cf0`. Initialization runs the actual recovered queue-resize child through set-state. Host handle allocation, virtual methods, diagnostic logging and cleanup registration remain explicit platform bridges.

Initialization sets its flag before setup, clears raw queue mode, creates the dispatch synchronizer only when absent, then resets capacity/cursors through set-state. Interface creation is attempted only when the interface handle is zero. The temporary interface is released after query even when query fails; a failed create-device stage does not execute that release. Setup failure runs cleanup without clearing the initialization flag. Cleanup registration occurs independently of setup success, and its callback result is ignored. The returned value is the final initialization flag, including changes made by callbacks.

Cleanup reloads the device handle between unacquire and release, clears it after release, then reloads/releases/clears the interface handle. Callback writes can change which handles are dispatched, and writes made later are not retroactively cleared. Shutdown calls this cleanup and then clears initialization while retaining the cleanup-registration flag. Set-state kind 0 clamps/reset the queue using the actual resize routine; kind 10 stores a callback identity. Other kinds update diagnostic file/line before logging and return zero independently of callback results.

The setup call at virtual offset `0x34` takes object, window handle and flags 6, with 12-byte callee cleanup. The window getter accepts no original arguments: the initializer's pushed 6 remains a third virtual-call argument. The initializer's initial pushed ECX is a temporary output slot, not evidence of a required fastcall parameter. Native code supplies its initial observation value explicitly; successful platform create-device calls populate it before use.

Complete global/queue/key/remap images and ordered platform observations are retained. Cleanup/shutdown are void and their return observations are normalized to zero; incidental EAX is not claimed as a return contract.
